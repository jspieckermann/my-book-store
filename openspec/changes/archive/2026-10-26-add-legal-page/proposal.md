## Why

The app ships third-party open-source code (Angular, RxJS, zod, etc.) but has no page disclosing those dependencies or their licenses. A "Legal" page listing them, reachable from the footer alongside the existing Impressum link, closes that gap.

## What Changes

- Add a new "Legal" page at a dedicated route listing every production dependency the app actually ships (direct and transitive — e.g. `@angular/core`, `rxjs`, `zod`, and everything else resolved under `dependencies` in `package.json`, excluding devDependencies/build tooling that never reaches the browser), each with its name, version, and license.
- The list is generated by a build-time script (following the existing `scripts/generate-trace-matrix.mjs` precedent) into a checked-in data file the page reads — not fetched at runtime and not computed from `devDependencies`.
- Add a "Legal" link to the footer, next to the existing Impressum link, reachable from every page.
- The Legal page follows the same conventions as the existing Impressum page: a breadcrumb back to the main page, and its own heading/labels translated to the selected UI language (the dependency data itself — names, versions, license identifiers — is factual and not translated, same posture as Impressum's fixed identity/VAT data).

## Capabilities

### New Capabilities
- `legal`: a page listing the app's production dependencies (including transitive) with name, version, and license, reachable at a dedicated route with a breadcrumb back to the main page and UI-language-following headings/labels.

### Modified Capabilities
- `app-footer`: the "Footer content" requirement changes to also render a link to the new Legal page, alongside the existing Impressum link.

## Impact

- Affected files: new `src/app/legal/` component (`.ts`/`.html`/`.css`/`.spec.ts`), a new `scripts/generate-legal-notices.mjs` (or similar) that writes a generated dependency-data file consumed by the component, `src/app/app.routes.ts` (new route), `src/app/footer/footer.html`/`.css` (new link), `src/app/language/translations.ts` (new `legal.*` keys).
- New npm script (e.g. `npm run legal`) to regenerate the dependency data file, analogous to `npm run trace`; the generated file is checked into the repo and must be manually regenerated when production dependencies change (same posture as `openspec/trace-matrix.md`).
- No new runtime dependency is introduced — the dependency list itself is generated at build/dev time from `package.json`/`node_modules`, not fetched or computed in the browser.
